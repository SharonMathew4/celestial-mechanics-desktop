1. Executive Summary & Key Metrics

The CelestialMechanics.Desktop project is a native Windows desktop application built with WPF and .NET 8, serving as the primary GUI front-end for an N-body gravitational simulation engine. The application features a cinematic dark theme, a multi-stage modal navigation system, a full 3-panel IDE workspace, and a hardware-accelerated OpenGL 3D viewport with procedural shader-based rendering of celestial bodies.

8. 3D Viewport & Rendering Pipeline

8.1 OpenGL Integration Architecture

The 3D viewport is implemented through a sophisticated multi-layer architecture:

  1. OpenGLHost (HwndHost) — Creates a native child HWND window with CS_OWNDC class style, sets up a WGL OpenGL context, and provides a Silk.NET.OpenGL.GL API object. DPI-aware pixel calculation via VisualTreeHelper.GetDpi().
  2. RenderLoop — Runs on a dedicated render thread at 60 FPS, owns the WGL context via wglMakeCurrent, handles frame pacing and FPS tracking.
  3. GLRenderer — Orchestrates the 5-pass rendering pipeline, managing all sub-renderers and shader programs.
  4. ViewportPanel — WPF UserControl wrapping the OpenGL host, handling all mouse/keyboard input delegation to the camera and ViewModel.

8.3 Camera System

The Camera class implements an orbit camera with smooth interpolation:

  • Orbit: Yaw/Pitch rotation around an adjustable target point
  • Pan: Shift+drag moves the target in the camera's right/up plane
  • Zoom: Scroll wheel adjusts orbital distance (0.1–10,000 range)
  • FOV Zoom: Shift+Scroll adjusts field of view (10°–120°)
  • WASD+QE: Keyboard navigation at 60Hz polling rate
  • Fly-to: Smooth cubic ease-in-out animation (0.8s duration) to focus on a body
  • Damping: All parameters use exponential smoothing (factor 8.0) for butter-smooth motion

14. Strengths & Achievements

  1. Professional-grade theming: 27 custom control templates with consistent color tokens, hover/press/disabled/selected states across all controls. The design language is cohesive and visually impressive.
  2. Sophisticated procedural rendering: 460-line fragment shader with Simplex noise fBm generates unique, animated visuals for 10 body types — no textures needed. Star convection, gas giant bands, and black hole rim glow are exceptionally well-implemented.
  3. Proper threading architecture: Three independent threads (UI at 20Hz, Render at 60Hz, Physics at ~1kHz) with thread-safe communication via locks and Interlocked atomic operations.
  4. Smooth camera system: Exponential damping on all 5 camera parameters (yaw, pitch, distance, target, FOV) with fly-to animation using cubic ease-in-out interpolation.
  5. Complete MVVM implementation: 11 ViewModels with source-generated properties/commands, event-driven inter-VM communication, and minimal code-behind (only View-specific concerns like OpenGL init and video playback).
  6. Full simulation settings exposure: All 20+ PhysicsConfig parameters accessible through the Settings panel, including advanced features like Barnes-Hut theta, relativistic effects, and adaptive timestep.
  7. Cinematic modal navigation: Multi-stage entry flow with background video, blur effects, and consistent modal styling creates a polished first impression.
  8. Body placement system: Complete Add mode workflow with palette selection, cursor change, XZ plane raycasting for placement, and right-click cancellation.

15.1 Technical Observations

  • MainWindowViewModel is overly large (707 lines) — handles navigation, modes, placement, simulation control, save/load, and metric updates. Should be decomposed into focused ViewModels.
  • No input validation on inspector TextBoxes — users can enter invalid values for mass, radius, etc. without warning.
  • Body Type Palette commands use a workaround with Tag property and Int32.MinValue CommandParameter — needs proper enum-based command parameter binding.
  • No error handling UX — file load errors are silently caught, save failures are invisible to users.
  • Accessibility — no ARIA-equivalent automation properties, no focus indicators on custom-templated controls, no high-contrast theme.
  • No animations between navigation states — modals appear/disappear instantly without transitions.
